# План разработки Telegram-бота и веб-кабинета преподавателя

Версия: 5 ноября 2026 года. Статус: рабочий план реализации.

Основа: [обновлённый сценарий MVP](./Сценарий%20работы%20Telegram-бота%20—%20MVP.md) и решения, принятые после его обновления. Прежние [схемы Miro](./Схемы%20сценариев%20Telegram-бота.md) описывают старую версию продукта и не являются источником требований для разработки.

## 1. Цель и текущее состояние

Первый продукт состоит из Telegram-бота для ученика и обычного веб-кабинета для преподавателя. Ученик изучает назначенные подборки, отвечает на вопросы, повторяет сложные слова, проходит ежедневную практику и экзамен. Преподаватель приглашает учеников, создаёт материалы, назначает подборки и смотрит результаты.

Сейчас в проекте есть локально запускаемый бот на Node.js, TypeScript и grammY. Он отвечает на Start и проводит демонстрационное упражнение с одним словом breakfast. Слово записано в коде; базы данных, ролей, привязки, веб-кабинета и сохранения ответов пока нет. Этот прототип подтверждает работу связи с Telegram, но учебную логику предстоит построить заново на данных из базы.

## 2. Подтверждённые продуктовые решения

| Тема | Решение |
| --- | --- |
| Формат | Ученик работает в Telegram-чате; преподаватель — в веб-кабинете. Mini App не требуется. |
| Роль преподавателя | Выдаётся вручную уполномоченным администратором проекта. Самостоятельной регистрации преподавателей нет. |
| Роли аккаунта | Один Telegram-аккаунт имеет одну роль: преподаватель или ученик. |
| Вход без приглашения | Бот показывает приветствие и предлагает запросить ссылку у преподавателя. |
| Связь | У ученика одновременно не более одного преподавателя. Ссылка другого преподавателя для уже привязанного ученика отклоняется. |
| Создание ученика | Преподаватель заранее создаёт запись ученика и затем формирует персональную ссылку. |
| Приглашение | Отдельная ссылка для каждого ученика, срок действия — 7 дней. |
| Подтверждение | Ученик подтверждает присоединение; преподаватель дополнительно подтверждает нужный Telegram-аккаунт с помощью проверочного кода. До подтверждения материалы не открываются. |
| Имя ученика | Преподаватель задаёт и при необходимости меняет своё отображаемое имя ученика. Имя и username Telegram хранятся отдельно для сверки; идентификатором служит Telegram ID. |
| Отвязка | Только преподаватель может убрать ученика из своего списка. Связь и право доступа преподавателя прекращаются; аккаунт ученика и его прогресс сохраняются. |
| Материалы | Преподаватель сам добавляет карточки и подборки. Подборку можно скопировать другому ученику; после копирования материалы редактируются независимо. |
| Результаты | Преподаватель видит назначенные подборки, просмотренные карточки, обе попытки ответа, сложные слова, ежедневную практику и экзамены только своих учеников. |
| Группы | Отдельных групп и классов в первом релизе нет. Преподаватель работает со списком учеников. |

После отвязки ученик может продолжать заниматься по уже полученным личным копиям материалов. Если позднее он примет приглашение другого преподавателя, новый преподаватель увидит только материалы и результаты, появившиеся в рамках новой связи. Это предлагаемое правило доступа; перед реализацией переноса ученика его нужно подтвердить отдельно.

## 3. Как будет работать привязка

1. Администратор проекта выдаёт конкретному Telegram ID роль преподавателя.
2. Преподаватель входит в кабинет через Telegram. Сервер проверяет вход и роль. Сам вход через Telegram не выдаёт роль.
3. В кабинете преподаватель создаёт запись ученика, задаёт удобное имя и получает персональную ссылку. У записи статус «Ожидает подключения».
4. Ссылка ведёт в бот с одноразовым случайным параметром. Она действует 7 дней, может быть отменена и не содержит имени ученика.
5. Ученик нажимает Start, видит имя преподавателя и подтверждает желание присоединиться. Бот фиксирует Telegram ID аккаунта и переводит заявку в статус «Ожидает подтверждения преподавателя».
6. Бот показывает ученику короткий проверочный код. Ученик сообщает его преподавателю через уже известный им канал связи. Преподаватель вводит код в кабинете и видит имя и username Telegram для дополнительной сверки.
7. После верного кода преподаватель подтверждает привязку. Статус становится «Подключён», ученику открываются назначенные материалы и бот может присылать ему уведомления.
8. Если ссылку открыл не тот человек, преподаватель отклоняет заявку и создаёт новую ссылку. Истёкшая, отменённая и уже использованная ссылки не дают доступ.

Если преподаватель назначил подборку до подключения ученика, назначение остаётся в базе. Бот отправляет уведомление после подтверждения связи; до этого ученик не получает материалы.

**Почему два подтверждения:** Telegram сообщает боту, какой аккаунт нажал Start, но не подтверждает, что аккаунт принадлежит человеку, которому преподаватель намеревался отправить ссылку. Проверочный код связывает Telegram-аккаунт с уже существующим способом общения преподавателя и ученика. Имя и username не считаются доказательством личности.

Ссылки генерируются криптографически случайным способом; сервер хранит их проверяемое представление, ограничивает срок и повторное использование. У проверочного кода также есть короткий срок, ограничение числа попыток и возможность перевыпуска. Конкретные значения для кода фиксируются при реализации интерфейса.

## 4. Веб-кабинет преподавателя

### 4.1. Вход и главная

- Кнопка входа через Telegram; после входа сервер проверяет назначенную роль.
- Главная страница показывает число учеников, заявки на подтверждение, недавно опубликованные подборки и последние результаты.
- При отсутствии роли преподавателя кабинет объясняет отсутствие доступа без показа чужих данных.

Для входа используем актуальный [Telegram Login](https://core.telegram.org/bots/telegram-login). Адрес кабинета и адрес возврата после входа регистрируются в BotFather. Проверка ответа Telegram и прав выполняется на сервере.

### 4.2. Ученики и приглашения

- Список: имя, Telegram-имя после подключения, статус, дата последней активности, ожидающие действия.
- Создание ученика и персональной ссылки; повторная выдача ссылки после истечения срока или отклонения.
- Экран проверки заявки: имя из Telegram, username при наличии, поле проверочного кода, кнопки подтверждения и отклонения.
- Карточка ученика: изменение отображаемого имени, назначенные подборки, прогресс, результаты.
- Действие «Убрать из моих учеников» с понятным предупреждением о последствиях. Оно прекращает доступ преподавателя, не стирая прогресс ученика.

### 4.3. Подборки и карточки

- Создание подборки и карточек: английское слово или фраза, основной русский перевод, необязательный пример и пояснение.
- Допустимые ответы задаются отдельно для направлений русский → английский и английский → русский; отдельно отмечаются разрешённые способы нормализации, например отсутствие to у конкретного глагола.
- Просмотр и редактирование карточек списком, предварительный просмотр того, как их увидит ученик.
- Копирование подборки конкретному ученику создаёт независимую копию. Обновление оригинала не меняет уже выданную копию без явного действия преподавателя.
- Публикация новой подборки и добавление карточек в уже доступную ученику подборку — разные действия с разными уведомлениями.
- До публикации преподаватель видит, какому ученику уйдёт подборка и какое сообщение бот отправит после подключения или сразу, если ученик уже подключён.
- Правка опубликованной карточки создаёт новую версию; старые ответы продолжают ссылаться на ту версию, на которую отвечал ученик.

### 4.4. Результаты

- По ученику: назначено, начато, завершено; просмотренные карточки; ответы с первой и второй попытки; текущие сложные слова и серия освоения; результаты ежедневной практики и экзамена.
- По подборке: кто получил, кто начал, кто завершил, какие слова вызвали затруднение.
- Результаты строятся из сохранённых попыток, а не из истории сообщений Telegram.
- Выгрузка в файл пока не согласована и в базовый объём не включена.

## 5. Сценарий ученика в боте

1. После подключения ученик видит меню: «Все слова», «Подборки», «Сложные слова», «Ежедневная практика», «Экзамен».
2. В «Подборках» он может просмотреть весь список карточек до практики и вернуться к нему позже. Новые карточки в дополненной подборке помечаются.
3. «Все слова» объединяет доступные карточки; одинаковое слово, полученное из нескольких подборок, показывается один раз с указанием источников.
4. Тест «Выбери перевод» работает в обоих направлениях. Неверные варианты берутся из других карточек и не совпадают с допустимыми ответами текущей.
5. После первой ошибки бот показывает верную пару и возвращает слово в конце короткой серии. После второй ошибки добавляет его в «Сложные». Результат с первой попытки и итог после повтора считаются отдельно.
6. В «Переведи меня» ученик вводит перевод текстом. Проверка сначала сравнивает явные допустимые варианты после согласованной нормализации. Похожесть написания «90%» не используется как автоматическое доказательство правильного смысла.
7. Сложное слово выходит из активного списка после пяти правильных ответов подряд с первой попытки в последующих практиках; ошибка обнуляет серию.
8. Раз в день бот предлагает новый короткий квест из сложных, новых и старых слов. Незавершённый квест продолжает тот же шаг; повторное напоминание не создаёт второй квест.
9. Экзамен использует доступные ученику слова из всех подборок и оба вида вопросов; точный объём экзамена ещё нужно согласовать.

Бот сохраняет текущий шаг, ответы и результаты в базе. Повторное нажатие старой кнопки показывает актуальное состояние и не записывает вторую попытку.

## 6. Предлагаемая техническая схема

- **Один проект на TypeScript:** существующий бот, серверные правила и веб-кабинет разрабатываются вместе и используют общие типы данных.
- **Веб-интерфейс:** компактное приложение на React для преподавателя; на телефоне доступны основные действия, ввод длинных подборок ориентирован на экран компьютера.
- **Сервер:** проверяет вход преподавателя, роль и право на конкретного ученика; обслуживает кабинет и принимает события бота.
- **База:** PostgreSQL хранит пользователей, связи, приглашения, материалы, версии карточек, занятия, попытки, сложные слова и уведомления.
- **Запуск:** при локальной разработке бот может получать события опросом, как сейчас. Для размещения вместе с кабинетом планируется публичный HTTPS-адрес и webhook Telegram.
- **Ежедневные задачи:** отдельный планировщик или задача внутри сервиса создаёт квест и уведомление. В базе фиксируется один квест на ученика и локальную дату, чтобы перезапуск не создавал дубликаты.

Для небольшого пилота достаточно одного веб-сервиса и одной базы. Если нагрузка вырастет, бот, кабинет и планировщик можно разнести по отдельным процессам, сохранив общую модель данных.

### Основные данные

| Сущность | Что хранит |
| --- | --- |
| Пользователь | Telegram ID, роль, Telegram-имя и настройки ученика. |
| Связь преподавателя и ученика | Преподаватель, ученик, имя, заданное преподавателем, статус и даты связи. |
| Приглашение и заявка | Срок ссылки, состояние, Telegram ID открывшего её аккаунта и результат проверки. |
| Подборка и личная копия | Исходный материал преподавателя, отдельная копия ученика, публикация и источник копирования. |
| Версия карточки | Текст, перевод, варианты ответа в двух направлениях, пример, правила нормализации и номер версии. |
| Занятие и попытка | Тип занятия, текущий шаг, версия карточки, направление, введённый или выбранный ответ, номер попытки, результат. |
| Сложное слово | Активность в списке, счётчик верных ответов подряд и история ошибок. |
| Уведомление | Кому и почему отправить сообщение, статус доставки и ключ от повторной отправки. |

## 7. Этапы реализации и проверки

### Этап 0. Зафиксировать учебные примеры

Подготовить 2–3 небольшие подборки с реальными словами, неоднозначными переводами, фразами, примерами с to и ответами с ё/е. На этих данных утвердить допустимые ответы, длину ежедневного квеста и экзамена. **Готово, когда:** одни и те же примеры можно использовать для проверки редактора и ответов бота.

### Этап 1. Сервер и база данных

Создать структуру проекта, схему базы и изменения схемы по версиям; перенести демонстрационное слово из кода в тестовые данные; настроить разные секреты для разработки и размещения. **Готово, когда:** бот читает карточку из базы, а перезапуск не теряет пользователя и занятие.

### Этап 2. Роли, вход и привязка

Вручную назначать роль преподавателя; сделать вход в кабинет, список учеников, персональные ссылки на 7 дней, подтверждение ученика и проверочный код преподавателя; обработать отклонение, истечение и повторное открытие ссылки. **Готово, когда:** один преподаватель безопасно подключает своего ученика, а другой преподаватель не видит эту связь.

### Этап 3. Редактор и публикация

Сделать подборки, карточки, допустимые варианты, предварительный просмотр, личные копии ученика, публикацию и версии исправленных карточек. **Готово, когда:** преподаватель сам создаёт подборку и выдаёт её ученику, а изменение одной копии не затрагивает другую.

### Этап 4. Словарь и тест с кнопками

Реализовать меню ученика, просмотр всех карточек, общий словарь, вопросы в двух направлениях, одну повторную попытку в конце серии и сохранение результата. **Готово, когда:** ученик проходит подборку, прерывает её, продолжает и получает точные результаты первой и второй попытки.

### Этап 5. Ввод перевода и сложные слова

Добавить «Переведи меня», безопасную нормализацию, явные допустимые ответы, вторую попытку, список сложных слов и правило пяти верных ответов подряд. **Готово, когда:** спорные примеры из этапа 0 оцениваются предсказуемо, а повторение не переписывает исходный результат.

### Этап 6. Ежедневная практика и экзамен

Добавить настройки времени и часового пояса, создание одного квеста в день, напоминания, продолжение незавершённого квеста и экзамен из доступных подборок. **Готово, когда:** перезапуск сервиса и повторная отправка уведомления не создают лишних занятий.

### Этап 7. Результаты преподавателя и пилот

Собрать страницы результатов, проверить права на каждом действии, резервное копирование, журнал ошибок, размещение и сценарии с несколькими преподавателями и учениками. **Готово, когда:** преподаватель видит только своих учеников, ученик — только свои материалы, а пилотная группа проходит полный цикл без ручного исправления данных.

## 8. Сквозные проверки перед пилотом

- Посторонний аккаунт открывает бот без ссылки; роль преподавателя не появляется.
- Ссылка истекла, отменена, использована повторно или переслана другому человеку.
- Ученик подтвердил вход, но преподаватель ещё не ввёл код: материалы недоступны.
- Уже привязанный ученик открывает приглашение другого преподавателя: новая связь отклонена.
- Преподаватель пытается открыть чужого ученика прямым адресом страницы или запросом к серверу: доступ запрещён.
- Преподаватель переименовал ученика: привязка по Telegram ID и история ответов не изменились.
- Преподаватель отвязал ученика: доступ преподавателя исчез, ученик сохранил прогресс и может продолжить самостоятельную практику.
- Подборка скопирована двум ученикам; правка одной копии не меняет вторую.
- Преподаватель исправил карточку после ответа ученика; сохранённая попытка продолжает ссылаться на прежнюю версию.
- Ученик дважды нажал старую кнопку или возобновил занятие после перезапуска: в базе одна попытка и верный текущий шаг.
- Первая ошибка и правильный повтор не превращаются в результат «верно с первой попытки».
- Ежедневный квест создаётся один раз по часовому поясу ученика; уведомление не отправляется тому, кто не нажал Start или отключил напоминания.

## 9. Ресурсы

**Разработка кабинета:** предварительно 180–290 часов. Оценка включает связь кабинета с ботом, но не учебные режимы бота из этапов 4–6; их нужно оценить после утверждения примеров и объёма вопросов.

| Часть кабинета | Ориентир |

| Вход через Telegram и права | 20–35 часов |

**Люди:** один разработчик, умеющий работать и с веб-интерфейсом, и с сервером; преподаватель или редактор для реальных карточек и проверки учебных правил; участники пилота для проверки сценариев. Отдельный дизайнер и тестировщик могут ускорить работу, но для первого пилота их задачи можно включить в работу небольшой команды.

**Размещение:** постоянно работающий сервис, PostgreSQL и резервные копии. Для пилота можно использовать адрес и HTTPS-сертификат провайдера без покупки отдельного домена. В качестве ориентира рассмотрен Railway: тариф Hobby начинается с $5 в месяц с включённым использованием, далее стоимость зависит от памяти, процессора и хранения. Рабочий бюджет небольшого пилота — ориентировочно $15–40 в месяц; это расчётный запас, а не фиксированный тариф. Проверить актуальные [тарифы](https://docs.railway.com/pricing/plans), [домены и HTTPS](https://docs.railway.com/networking/public-networking) и [резервные копии](https://docs.railway.com/volumes/backups) перед размещением.

## 10. Решения, которые ещё нужны

1. Сколько карточек в ежедневном квесте и сколько вопросов в обычном экзамене; нужен ли полный экзамен по всему словарю; какое время напоминания предлагать по умолчанию.
2. Реальные примеры допустимых переводов, правила ё/е, пунктуации и отсутствие to у отдельных карточек.
3. Нужен ли ограниченный допуск к опечаткам в длинных ответах; до утверждения примеров не применять правило «90%».
4. Видит ли новый преподаватель историю занятий ученика до новой привязки. Рекомендация этого плана — не видит.
5. Нужна ли выгрузка результатов из кабинета; сейчас предусмотрен просмотр на сайте.

Эти пункты не блокируют этапы 1–3, кроме примеров карточек, необходимых для проверки редактора.
