## 1. Цель и текущее состояние

Первый продукт состоит из Telegram-бота для ученика и обычного веб-кабинета для преподавателя. Ученик изучает выданные подборки, отвечает на вопросы, повторяет сложные слова, проходит ежедневную практику и экзамен, видит свой прогресс. Преподаватель приглашает учеников, создаёт материалы, выдаёт подборки и смотрит результаты.

**Что есть сейчас:**

- этапы 1–6 реализованы: база и миграции, роли, вход, привязка, кабинет преподавателя, меню ученика, словарь, подборки, тест с кнопками, редактор подборок и карточек, импорт, выдача и копии учеников, «Переведи меня» с вводом ответа и второй попыткой, «Сложные слова» с практикой по всему списку или выбранным словам, правило «5 из 5» и возврат освоенного слова, «Настройки» (часовой пояс, время и включение напоминаний), ежедневный квест — один на локальную дату ученика, вчерашний закрывается как незавершённый, — напоминания через планировщик раз в минуту и очередь уведомлений, экзамен и экран «Мой прогресс»;
- для проверки со стороны ученика есть `npm run dev:prepare-student -- [telegram_id] [--reset] [--hard[=N]] [--tz=<пояс>] [--remind]`: подключает аккаунт к преподавателю для разработки, выдаёт три тестовые подборки, по флагу `--reset` сбрасывает прогресс (вместе с квестами, экзаменами и напоминаниями), по флагу `--hard` отмечает N слов (по умолчанию 3) сложными — у первого серия 4 из 5, и один верный ответ в новом занятии его освоит, — по флагу `--tz` задаёт часовой пояс IANA, а по флагу `--remind` ставит время напоминания на текущую минуту (без пояса — Москва): запущенный сервис в течение минуты создаст квест и пришлёт напоминание с кнопкой «Начать»;
- этап 7 реализован: страницы результатов ученика (занятия всех видов, ответы с первой попытки и после повтора, сложные и освоенные слова с серией «5 из 5», просмотренные карточки, квесты, экзамены, прогресс) и подборки (кто получил, начал и завершил, трудные слова), последние результаты и недавно выданные подборки на главной, выгрузка результатов ученика в CSV для Excel с защитой от формул; всё строго в рамках текущей связи. Каждый маршрут API кабинета проходит единую проверку роли и права на объект, тесты перебирают все маршруты контракта. Журнал ошибок — строки JSON в stdout без секретов, пользователю показываются только общие сообщения;
- подготовлено размещение на Railway, но **само размещение не выполнялось**: `Dockerfile`, `railway.json` (миграции перед запуском, проверка `/health`), webhook с секретным токеном обязателен при `NODE_ENV=production`, скрипт резервной копии `npm run db:backup`. Порядок действий, переменные и восстановление — в документе [«Развёртывание и резервные копии»](./Развёртывание%20и%20резервные%20копии.md);
- для проверки кабинета без Telegram есть `npm run dev:student-practice -- <telegram_id> [--wrong=слово1,слово2]`: ученик проходит тест по каждой своей подборке, слова из `--wrong` дважды отвечает неверно, и в кабинете появляются результаты;
- настоящий Telegram и вход через него ещё не проверялись: связь с Telegram в автотестах и сквозном прогоне заменена заглушкой, запуск в режиме размещения проверен с локальной заменой Bot API;
- репозиторий Git подключён к `origin` (`eldrssn/english-bot`), файл `.env` с токеном в него не попадает.

## 2. Подтверждённые продуктовые решения

### 2.1. Формат и пилот

| Тема | Решение |
| --- | --- |
| Формат | Ученик работает в Telegram-чате, преподаватель — в веб-кабинете. Mini App не требуется. |
| Пилот | 1 преподаватель, до 20 учеников, **только взрослые**. Несовершеннолетних подключаем после оформления согласий и проверки юристом. |
| География | Смешанная: ученики и в РФ, и за её пределами. Часовые пояса разные. |
| Размещение | После реализации всех этапов — Railway, тариф Hobby ($5 в месяц): один сервис и одна база. До этого сервис запускается локально на компьютере разработчика. Для учеников из РФ нужна юридическая проверка до подключения реальных людей (см. раздел 11); запасной вариант для пилота в РФ — российский хостинг, например Amvera или Timeweb Cloud. |
| Функции концепции, которых не будет | Fill in the Blanks и письменная практика со своей фразой. Группы и классы тоже не входят в первый релиз. |
| Что добавлено | Экран прогресса ученика, пункт меню «Настройки», импорт карточек из CSV, выгрузка результатов в CSV. |
| Удаление данных по запросу | В пилоте не реализуется. Это тоже вопрос к юристу перед подключением реальных учеников. |

### 2.2. Роли и привязка

| Тема | Решение |
| --- | --- |
| Роль преподавателя | Выдаётся вручную администратором проекта. Самостоятельной регистрации преподавателей нет. |
| Роли аккаунта | Один Telegram-аккаунт имеет одну роль: преподаватель или ученик. |
| Вход без приглашения | Бот показывает приветствие и предлагает запросить ссылку у преподавателя. |
| Связь | У ученика одновременно не более одного преподавателя. Ссылка другого преподавателя для уже привязанного ученика отклоняется. |
| Незавершённая заявка | Если есть заявка к преподавателю А и открыта ссылка преподавателя Б, бот спрашивает ученика, переходить ли. Активна всегда одна заявка. |
| Приглашение | Преподаватель заранее создаёт запись ученика и получает отдельную ссылку на 7 дней. |
| Подтверждение | Ученик подтверждает присоединение, преподаватель вводит проверочный код. До этого материалы не открываются. |
| Проверочный код | 6 цифр, действует 24 часа, 5 попыток, можно перевыпустить. |
| Уведомление о заявке | Бот пишет преподавателю; заявка также видна на главной кабинета. |
| Имя ученика | Преподаватель задаёт и меняет своё отображаемое имя. Имя и username Telegram хранятся отдельно для сверки; идентификатор — Telegram ID. |
| Отвязка | Только преподаватель может убрать ученика из своего списка. Аккаунт и прогресс ученика сохраняются. |
| После отвязки | Ученик занимается по уже полученным личным копиям, но новых материалов не получает. |
| История при новой связи | Преподаватель видит только материалы и результаты текущей связи, **даже если ученик вернулся к нему**. |

### 2.3. Материалы и результаты

| Тема | Решение |
| --- | --- |
| Создание | Преподаватель сам добавляет карточки и подборки: вручную или импортом из CSV. |
| Выдача | Одним действием можно выдать подборку нескольким ученикам; каждому создаётся независимая личная копия. |
| Правка оригинала | Уже выданные копии не меняет, кнопки «обновить копии» нет. Копии правятся по отдельности. |
| Удаление карточки | Карточка исчезает из словаря, «Сложных» и будущих вопросов, история ответов сохраняется. Уже заданный вопрос завершается по старой версии. |
| Правка карточки | Создаёт новую версию; старые ответы ссылаются на прежнюю. Серия «5 из 5» не сбрасывается. |
| «Завершил подборку» | Ученик ответил по всем действующим карточкам хотя бы на один вопрос. После добавления слов статус снова становится «Практикует». |
| Видимость результатов | Преподаватель видит подборки, просмотренные карточки, обе попытки ответа, сложные слова, практику и экзамены только своих учеников в рамках текущей связи. |
| Выгрузка | Результаты ученика скачиваются в CSV. |
| Импорт | Вставка строк из Google Таблиц или Excel и файл CSV. Столбцы: слово, перевод, пример, пояснение, дополнительные ответы ru→en и en→ru через «;», можно без `to`. Обязательны первые два. |
| Дубли в подборке | Строка с тем же словом и тем же переводом не добавляется и помечается при импорте и ручном вводе. Слово с другим переводом (`bank — берег`) добавляется. |
| Удаление подборки | Оригинал и копии удаляются отдельно. Удаление оригинала убирает его из списка преподавателя, выданные копии остаются у учеников. «Забрать у ученика» скрывает копию из бота, история ответов сохраняется. |
| Тестовые подборки | Для разработки `npm run dev:prepare-student` заводит три тестовые подборки у преподавателя для разработки, их можно править и выдавать через кабинет. |

**Следствие решения «без обновления копий».** Чтобы добавить слова сразу нескольким ученикам, преподавателю придётся править каждую копию или выдать новую подборку. При 20 учениках это заметно; если на пилоте станет неудобно, добавим массовое действие отдельной задачей.

### 2.4. Обучение

| Тема | Решение |
| --- | --- |
| Одно слово | Слова считаются одним, только если совпали и английский текст, и основной перевод. `bank — банк` и `bank — берег` остаются разными словами. |
| Счётчик «5 из 5» | Один на слово, засчитывается любое направление. Повтор после ошибки идёт в том же направлении. |
| Объёмы | Квест — 10 вопросов, экзамен — 20 вопросов. Значения задаются настройками. |
| Вчерашний квест | Закрывается как незавершённый, ответы сохраняются, создаётся новый. Неотвеченные слова могут попасть в новый квест. |
| Проверка ввода | Без допуска к опечаткам. Сравнение с явными вариантами после нормализации: регистр, пробелы, пунктуация, `ё = е`, отсутствие `to`, если разрешено в карточке. Правило «90%» не используется. |
| Напоминания | По умолчанию в 19:00 по часовому поясу ученика; пояс выбирается при подключении. |
| Возврат освоенного слова | Верный ответ на повторе после подсказки не прерывает серию ошибок: «ошибка, верный повтор, ошибка в следующем занятии» возвращает слово в «Сложные». Сбрасывает счётчик ошибок только верный ответ с первой попытки. |
| Неверные варианты | Не показывается вариант, который по смыслу тоже верен: на вопрос `bank` нет кнопки «берег» из `bank — берег`. Если вариантов не хватает, слово спрашивается вводом текста (с этапа 5). |

### 2.5. Значения, выбранные разработчиком

Заказчик их отдельно не обсуждал. Все они легко меняются; при возражении поправим до соответствующего этапа.

| Тема | Значение |
| --- | --- |
| Короткая серия | 5 вопросов, затем повтор ошибок этой серии. |
| Кнопки в тесте | 4 варианта: один верный и три неверных. Если неверных вариантов меньше, показываем сколько есть; при отсутствии неверных вариантов тест по этому слову недоступен, предлагается «Переведи меня». |
| Состав квеста | До 5 сложных, до 3 недавно добавленных, остальное — старые слова. Нехватку одной группы восполняем из других. |
| Пустой словарь | Квест не создаётся, напоминание не отправляется. Экзамен и тест объясняют, что слов пока нет. |
| Экзамен | Равномерная выборка из подборок. Если слов меньше 20, в экзамен входят все. Полный экзамен по словарю — позже. |
| Занятие | Текущее занятие у ученика одно. Новое занятие ставит прежнее на паузу, к нему можно вернуться. Вчерашний квест не возобновляется. |
| «5 из 5» за одно занятие | Одно слово получает не больше одного засчитанного ответа за занятие. |
| Часовой пояс не выбран | Напоминания не отправляются, бот снова предлагает выбрать пояс при следующем входе. |
| Срок заявки | Заявка действует 7 дней с момента подтверждения учеником. |
| Формат файлов | CSV в UTF-8. При импорте разделитель `,` или `;` определяется автоматически, можно также вставить строки из таблицы. |
| Статусы подборки | «Назначено» — выдана; «Начал» — открыл карточки; «Практикует» — есть ответы; «Завершил» — см. раздел 2.3. |
| Запуск «Переведи меня» | Кнопкой в подборке рядом с тестом. Тест и «Переведи меня» по одной подборке — отдельные занятия, каждое продолжается своей кнопкой. |
| Ответ без букв | Сообщение из одной пунктуации, смайликов или пробелов попыткой не считается: бот просит написать перевод словами. |
| Ответ, отправленный раньше вопроса | Не засчитывается следующему вопросу (например, при двойной отправке): бот сравнивает номер сообщения с номером показа вопроса и показывает вопрос снова. |
| Практика сложных слов | Вопросы чередуют кнопки и ввод в обоих направлениях. Слова для частичной практики отмечаются кнопками на странице списка. Новая практика другого набора закрывает прежнюю как незавершённую, ответы сохраняются. |
| «Недавно добавленное» слово в квесте | Первая карточка слова появилась у ученика не раньше 7 дней назад. Нехватку группы восполняют старые слова, затем оставшиеся сложные, затем недавние. Освоенные слова берутся, только если изучаемых не хватило. |
| Окно напоминания | С наступления времени ученика до конца его дня: если сервис простаивал в 19:00, напоминание придёт после перезапуска в тот же день. Одно на локальную дату; если сегодняшний квест уже пройден, напоминания нет. |
| Создание квеста | Планировщик создаёт квест вместе с напоминанием, на паузе: текущее занятие ученика не прерывается. Ученик может начать его и раньше, кнопкой в «Ежедневной практике». В списке «Продолжить» меню квест появляется после первого вопроса. |
| Квест без часового пояса | Недоступен: день ученика неизвестен. Раздел предлагает выбрать пояс. |
| Смена часового пояса | Открытый квест другой даты закрывается как незавершённый, ответы сохраняются. |
| Серия дней | Дни подряд с завершённым квестом. Сегодняшний ещё не пройденный квест серию не обрывает, пропущенный день обрывает. |
| «Изученные» слова в прогрессе | Доступные слова, на которые есть хотя бы один ответ в любом режиме. |
| Выборка экзамена | Подборки обходятся по кругу, из каждой по очереди берётся случайное слово. Незавершённый экзамен продолжается, второй не создаётся. В итоге отдельно ошибки (неверно с первой попытки) и слова, попавшие в «Сложные». |
| Выбор пояса и времени | Пояс — из списков «Россия», «Другие страны» и «Смещение от UTC». Время напоминания — целый час. |
| Границы результатов | Попытки, просмотры и занятия считаются по ссылке на связь, записанной в момент действия. Ответы после отвязки и ответы по копиям прежней связи не видны никому из преподавателей. Квест, экзамен и практика сложных слов охватывают весь словарь ученика, поэтому в них могут встретиться слова из копий прежней связи: их ответы видит текущий преподаватель. |
| Слова в результатах | Слова из подборок текущей связи и слова, на которые ученик отвечал в её рамках, с текущим состоянием («сложное», «изучается», «освоено») и серией. Состояние слова одно на ученика, поэтому оно может отражать и прежнюю работу над тем же словом. |
| Файл выгрузки | Один CSV на ученика с разделами: сводка, подборки, занятия, ответы, слова, просмотры. UTF-8 с BOM, разделитель `;` (Excel с русскими настройками открывает без мастера импорта), строки CRLF, даты в часовом поясе ученика или в UTC. Значение, начинающееся с `=`, `+`, `-`, `@`, табуляции или перевода строки, получает апостроф впереди. |
| Результаты по подборке | Только ученики текущего списка и ответы в рамках связи, выдавшей копию. «Трудные слова» — с ошибкой с первой попытки или в «Сложных» у кого-то сейчас; сначала больше ошибок. |
| Главная | До 5 недавно выданных подборок и до 5 последних завершённых занятий текущих учеников. |
| Размещение | Docker-образ, миграции командой перед запуском новой версии, только webhook при `NODE_ENV=production`; адрес webhook по умолчанию совпадает с адресом кабинета. Журнал — JSON в stdout, хранится средствами Railway. |

## 3. Как работает привязка

1. Администратор выдаёт конкретному Telegram ID роль преподавателя командой на сервере. Действие записывается в журнал. На экране «нет доступа» пользователь видит свой Telegram ID, чтобы сообщить его администратору.
2. Преподаватель входит в кабинет через Telegram. Сервер проверяет вход и роль. Сам вход роль не выдаёт.
3. В кабинете преподаватель создаёт запись ученика, задаёт имя и получает персональную ссылку. Статус записи — «Ожидает подключения». Telegram-аккаунта у записи пока нет.
4. Ссылка ведёт в бот со случайным параметром. Она действует 7 дней, может быть отменена и не содержит имени ученика.
5. Ученик нажимает Start, видит имя преподавателя и подтверждает присоединение. Простое открытие ссылки её не расходует. После подтверждения ссылка считается использованной, бот фиксирует Telegram ID, статус становится «Ожидает подтверждения преподавателя».
6. Бот показывает ученику проверочный код, а преподавателю присылает уведомление о заявке. Ученик сообщает код через уже известный им канал связи. Преподаватель вводит код в кабинете и дополнительно сверяет имя и username.
7. После верного кода преподаватель подтверждает привязку. Статус — «Подключён». Бот предлагает ученику выбрать часовой пояс, открывает материалы и присылает уведомления об уже выданных подборках.
8. Если ссылку открыл не тот человек, преподаватель отклоняет заявку и создаёт новую ссылку.

**Почему два подтверждения.** Telegram сообщает боту, какой аккаунт нажал Start, но не подтверждает, что аккаунт принадлежит нужному человеку. Код связывает аккаунт с уже существующим способом общения преподавателя и ученика. Имя и username доказательством личности не считаются.

### Особые случаи

| Ситуация | Поведение |
| --- | --- |
| Ссылка истекла, отменена или уже использована | Бот сообщает, что ссылка недействительна, и советует запросить новую. Детали заявки не раскрываются. |
| Открыта ссылка другого преподавателя при активной связи | Отказ: сначала прежний преподаватель должен убрать ученика из списка. |
| Открыта ссылка Б при незавершённой заявке к А | Вопрос ученику. При согласии заявка к А отменяется, преподаватель А видит это и может создать новую ссылку. |
| Повторно открыта ссылка своей незавершённой заявки | Бот снова показывает действующий код или предлагает новый. |
| Ссылку открыл аккаунт преподавателя | Отказ: один аккаунт не может быть и преподавателем, и учеником. |
| Преподаватель отклонил заявку | Бот сразу сообщает ученику, что заявка не подтверждена, без подробностей, и советует запросить новую ссылку. |
| Код истёк или исчерпаны 5 попыток | Код перестаёт действовать. Ученик запрашивает новый в боте, пока заявка жива. |
| Ученика делают преподавателем | Администратор может сменить роль только при отсутствии активной связи и незавершённой заявки. |
| Подборка выдана до подключения | Копия хранится в базе. Уведомление уходит после подтверждения связи, преподаватель видит статус «Не подключён». |

**Безопасность.** Токен ссылки создаётся криптографически случайным способом и укладывается в лимит Telegram на параметр Start (64 символа). В базе хранится только его хэш. Код тоже хранится хэшем, число попыток считается на сервере.

## 4. Веб-кабинет преподавателя

### 4.1. Вход и главная

- Кнопка входа через Telegram; после входа сервер проверяет роль.
- Главная показывает число учеников, заявки на подтверждение, недавно выданные подборки и последние результаты.
- Без роли преподавателя кабинет объясняет отсутствие доступа, показывает Telegram ID и не показывает чужих данных.

Используем актуальный [Telegram Login](https://core.telegram.org/bots/telegram-login) — поток OpenID Connect (Authorization Code с PKCE):

- в BotFather в разделе Login Widget регистрируются адрес кабинета и адрес возврата, там же выдаются Client ID и Client Secret;
- сервер проверяет подпись `id_token` по JWKS Telegram, а также `iss`, `aud` и `exp`;
- запрашиваем `telegram:bot_access`, чтобы бот мог писать преподавателю о заявках;
- документация не говорит, работает ли вход на localhost, поэтому для разработки может понадобиться HTTPS-туннель.

Сессия кабинета хранится в cookie с флагами `HttpOnly`, `Secure`, `SameSite`. Изменяющие запросы защищены от CSRF.

### 4.2. Ученики и приглашения

- Список: имя, Telegram-имя после подключения, статус, дата последней активности, ожидающие действия.
- Создание ученика и ссылки; отмена ссылки; новая ссылка после истечения срока или отклонения.
- Экран заявки: имя из Telegram, username при наличии, поле кода, кнопки подтверждения и отклонения.
- Карточка ученика: изменение имени, выданные подборки, прогресс, результаты, выгрузка в CSV.
- Действие «Убрать из моих учеников» с предупреждением: доступ преподавателя прекратится, ученик сохранит прогресс и копии, но не получит новых материалов.

### 4.3. Подборки и карточки

- Создание подборки и карточек: английское слово или фраза, основной русский перевод, необязательные пример и пояснение.
- Допустимые ответы задаются отдельно для направлений ru→en и en→ru; у конкретной карточки можно разрешить отсутствие `to`.
- Импорт из CSV или вставка из таблицы: предварительный просмотр, ошибки по строкам, подсказка о дублях. Ничего не сохраняется до подтверждения.
- Просмотр и редактирование списком, предварительный просмотр карточки глазами ученика.
- Выдача одному или нескольким ученикам создаёт независимые копии.
- Перед выдачей преподаватель видит, кто и какое сообщение получит: сразу или после подключения.
- Новая подборка и добавление карточек в копию — разные действия с разными уведомлениями.
- Правка выданной карточки создаёт новую версию. Удаление скрывает карточку, не стирая историю.

### 4.4. Результаты

- По ученику: назначено, начато, завершено; просмотренные карточки; ответы с первой и второй попытки; текущие сложные слова и серия «5 из 5»; ежедневная практика и экзамены.
- По подборке: кто получил, начал и завершил, какие слова вызвали затруднение. Копии объединяются по исходной подборке и исходной карточке.
- Результаты строятся из сохранённых попыток, а не из истории сообщений Telegram.
- Выгрузка результатов ученика в CSV. Значения, которые таблица может принять за формулу, экранируются.
- Все запросы ограничены текущей связью: результаты прежних связей не показываются.

## 5. Ученик в боте

Точное поведение описано в [сценарии](./Сценарий%20работы%20Telegram-бота%20—%20MVP.md). Кратко:

1. Меню: «Все слова», «Подборки», «Сложные слова», «Ежедневная практика», «Экзамен», «Мой прогресс», «Настройки».
2. Учебные режимы: просмотр карточек, тест «Выбери перевод», «Переведи меня» с вводом ответа.
3. После первой ошибки бот показывает верную пару и повторяет вопрос в конце короткой серии. После второй ошибки слово попадает в «Сложные».
4. Слово уходит из активного списка после пяти верных ответов подряд с первой попытки в последующих занятиях.
5. Прогресс показывает доступные, изученные, сложные и освоенные слова, завершённые подборки и серию дней с завершённым квестом.

## 6. Техническая схема

| Часть | Выбор | Почему |
| --- | --- | --- |
| Язык | TypeScript во всём проекте | Общие типы для бота, сервера и кабинета; прототип уже на нём. |
| Бот | grammY, состояние занятий только в базе | Переживает перезапуски и повторные нажатия. |
| Сервер | Fastify, проверка данных через Zod | Один сервис принимает webhook, отдаёт API и кабинет. |
| Кабинет | React и Vite | Компактное приложение; длинные подборки ориентированы на компьютер, основные действия доступны на телефоне. |
| База | PostgreSQL, Drizzle с миграциями | Ограничения базы гарантируют отсутствие дублей. |
| Тесты | Vitest на настоящем PostgreSQL, Playwright для кабинета | Проверки прав и дублей без настоящей базы бессмысленны. |
| Запуск | Локально опрос Telegram, на сервере webhook с секретным токеном | Как в прототипе при разработке, без постоянного опроса на сервере. |
| Размещение | Один сервис и одна база на Railway | Для пилота этого достаточно; при росте бот, кабинет и планировщик можно разнести. |

### Как обеспечивается надёжность

- **Логика обучения** вынесена в чистые функции без Telegram и базы: нормализация, проверка ответа, повторы, серии, состав квеста. Они покрываются тестами на примерах.
- **Вопрос сохраняется до отправки** вместе с вариантами и направлением. Кнопка содержит только ID вопроса и номер варианта, что укладывается в лимит Telegram на данные кнопки (64 байта).
- **Старая кнопка не создаёт попытку:** уникальное ограничение на вопрос и номер попытки плюс транзакция. Бот показывает актуальное состояние.
- **Текстовый ответ** относится только к открытому вопросу текущего занятия. Если такого вопроса нет, бот предлагает меню.
- **Повтор события Telegram:** `update_id` запоминается, повторная доставка ничего не меняет.
- **Уведомления** сначала записываются в очередь в базе с ключом от повторов. Обработчик отправляет их с учётом лимитов Telegram, а если ученик заблокировал бота, отмечает это в статусе.
- **Квесты:** планировщик раз в минуту ищет учеников, у которых наступило время напоминания. `unique(ученик, локальная дата)` исключает второй квест.
- **Доступ:** все запросы кабинета проходят через единую проверку права преподавателя на текущую связь. Попытки хранят ссылку на связь, поэтому история прежних связей отделена с самого начала.
- **Длинные списки** в боте разбиваются на страницы: сообщение Telegram ограничено 4096 символами.

### Основные данные

| Сущность | Что хранит |
| --- | --- |
| Пользователь | Telegram ID, роль, Telegram-имя и username, часовой пояс, время напоминаний, их включение, статус блокировки бота. |
| Запись ученика и связь | Преподаватель, имя от преподавателя, ученик (пусто до подключения), статус, даты начала и конца. Новая связь — новая запись, даже с тем же преподавателем. |
| Приглашение и заявка | Хэш токена, срок, состояние, Telegram ID открывшего, хэш кода, срок кода, число попыток, результат. |
| Исходная подборка и карточка | Материал преподавателя. |
| Личная копия и карточка копии | Копия ученика, связь, в рамках которой выдана, ссылка на источник, дата публикации, статус, удаление. |
| Версия карточки | Текст, перевод, варианты ответа по направлениям, пример, пояснение, разрешение пропуска `to`, номер версии. |
| Слово ученика | Ученик, нормализованные английский текст и перевод (уникально), статус «сложное» или «освоено», счётчик серии. Карточки разных копий ссылаются на него. |
| Занятие | Тип, статус (текущее, на паузе, завершено, не завершено), связь, локальная дата для квеста, порядок вопросов. |
| Вопрос и попытка | Версия карточки, слово, направление, формат, варианты, номер попытки, ответ, результат. |
| Просмотр карточки | Какую карточку и когда видел ученик. |
| Уведомление | Получатель, причина, ключ от повторов, статус доставки. |
| Журнал администратора | Кто, когда и кому менял роль. |

Как устроено слово при правке и нескольких копиях:

- Варианты ответа совпавших карточек объединяются: верным считается ответ из любой действующей карточки, и такие ответы не попадают в неверные варианты.
- Слово исчезает из показа, только когда у него не осталось действующих карточек.
- Если правка меняет основной перевод, карточка переходит к новому слову вместе с серией и статусом. Если такое слово уже есть, они объединяются: остаётся меньшая серия, а статус «сложное» сохраняется, если он был хотя бы у одного.

## 7. Этапы реализации

Порядок изменён: тест с кнопками идёт раньше редактора. Редактор — самая большая часть кабинета, а отзывы об учебных правилах могут изменить модель карточки.

**Порядок работы:** этапы 1–3 выполняются подряд, затем остановка на проверку заказчиком. Коммиты и отправка в репозиторий — только по прямой просьбе.

### Этап 0. Требования и примеры — в работе

Решения зафиксированы в этом документе. Подготовить 2–3 тестовые подборки с неоднозначными переводами, фразами, примерами с `to` и ответами с `ё/е`, а также ожидаемыми результатами проверки. **Готово, когда:** на одних и тех же примерах можно проверять логику и редактор. Реальные карточки преподавателя проверяются перед пилотом.

### Этап 1. Сервер и база

Структура проекта, схема и миграции, загрузка тестовых подборок, разные секреты для разработки и размещения, запуск тестов на PostgreSQL. **Готово, когда:** бот читает карточку из базы, а перезапуск не теряет пользователя и занятие.

### Этап 2. Роли, вход и привязка

Команда администратора, вход через Telegram, список учеников, ссылки, подтверждение учеником, код, уведомление преподавателю, отклонение, отвязка, все особые случаи из раздела 3. **Готово, когда:** преподаватель безопасно подключает своего ученика, а другой преподаватель не видит эту связь.

### Этап 3. Словарь и тест с кнопками

Меню ученика, просмотр карточек, «Все слова» с объединением, вопросы в двух направлениях, повтор в конце серии, сохранение и продолжение занятия. Подборки пока выдаются служебной командой из тестовых данных. **Готово, когда:** ученик проходит подборку, прерывает, продолжает и получает точные результаты первой и второй попытки. **Здесь остановка на проверку.**

### Этап 4. Редактор и выдача

Подборки, карточки, допустимые варианты, импорт CSV, предварительный просмотр, выдача нескольким ученикам, версии, удаление, уведомления о новой подборке и дополнении. **Готово, когда:** преподаватель сам создаёт подборку и выдаёт её, а изменение одной копии не затрагивает другую.

### Этап 5. Ввод перевода и сложные слова

«Переведи меня», нормализация, вторая попытка, список сложных слов, практика по ним, правило «5 из 5», возврат освоенного слова. **Готово, когда:** спорные примеры оцениваются предсказуемо, а повторение не переписывает исходный результат.

### Этап 6. Практика, экзамен и прогресс

Настройки, выбор часового пояса, один квест в день, напоминания, закрытие вчерашнего квеста, экзамен, экран прогресса. **Готово, когда:** перезапуск сервиса и повторная отправка уведомления не создают лишних занятий.

### Этап 7. Результаты и пилот — реализован, размещение ждёт заказчика

Страницы результатов, выгрузка в CSV, проверка прав на каждом действии, резервные копии, журнал ошибок, размещение на Railway, сценарии с несколькими преподавателями и учениками. **Готово, когда:** преподаватель видит только своих учеников, ученик — только свои материалы, а пилотная группа проходит полный цикл без ручного исправления данных. Автотестом проверено: два преподавателя и три ученика проходят полный цикл (`test/pilot/pilot-cycle.test.ts`). Осталось само размещение и пилот с реальными людьми (раздел 10).

## 8. Сквозные проверки перед пилотом

**Доступ и привязка**

- Посторонний аккаунт открывает бот без ссылки; роль преподавателя не появляется.
- Ссылка истекла, отменена, использована повторно или переслана другому человеку.
- Открытие ссылки без подтверждения не расходует её.
- Ученик подтвердил вход, но код ещё не введён: материалы недоступны.
- Код истёк или исчерпаны 5 попыток: старый код не работает, новый можно запросить.
- Уже привязанный ученик открывает приглашение другого преподавателя: новая связь отклонена.
- Ученик с незавершённой заявкой открывает ссылку другого преподавателя и соглашается: активна только новая заявка.
- Преподаватель открывает ссылку ученика: отказ.
- Преподаватель пытается открыть чужого ученика прямым адресом или запросом к серверу: доступ запрещён.
- Преподаватель переименовал ученика: привязка и история не изменились.
- Преподаватель отвязал ученика: доступ преподавателя исчез, ученик занимается по копиям, новые материалы не приходят.
- Ученик вернулся к прежнему преподавателю: виден только новый период.

**Материалы**

- Подборка выдана двум ученикам; правка одной копии не меняет вторую, правка оригинала не меняет обе.
- Преподаватель исправил карточку после ответа; попытка ссылается на прежнюю версию, серия «5 из 5» не сброшена.
- Преподаватель удалил карточку: она пропала из словаря, «Сложных» и будущих вопросов, заданный вопрос завершился, история сохранилась.
- Импорт с ошибочными строками ничего не сохраняет без подтверждения и показывает ошибки.
- В выгрузке значение, начинающееся с `=`, не исполняется как формула.

**Обучение**

- `bank — банк` и `bank — берег` остаются разными словами; одинаковая пара из двух подборок показывается один раз, серия у неё общая.
- Ученик дважды нажал старую кнопку или возобновил занятие после перезапуска: в базе одна попытка и верный текущий шаг.
- Первая ошибка и верный повтор не превращаются в «верно с первой попытки» и не увеличивают серию.
- Текст, присланный без открытого вопроса, не записывается как ответ.
- При нескольких занятиях ответ попадает только в текущее.
- В словаре меньше четырёх слов: тест показывает меньше кнопок или предлагает ввод, без ошибки.
- Ежедневный квест создаётся один раз по часовому поясу ученика, вчерашний закрывается как незавершённый.
- Напоминание не уходит тому, кто отключил его, заблокировал бота, не выбрал пояс или не имеет слов.

## 9. Ресурсы

**Разработка:** предварительно 310–510 часов. Это ориентир, а не обязательство.

| Часть | Ориентир |
| --- | ---: |
| Вход через Telegram и права | 20–35 часов |
| Ученики, приглашения, подтверждение, переименование и отвязка | 35–55 часов |
| Редактор, копии и публикация | 65–100 часов |
| Импорт CSV и выгрузка результатов | 12–23 часа |
| Просмотр результатов | 30–50 часов |
| Общая база, проверки и размещение | 30–50 часов |
| **Итого кабинет** | **192–313 часов** |
| Учебные режимы бота: этапы 3, 5 и 6 (грубая оценка) | 120–200 часов |
| **Всего** | **312–513 часов** |

**Люди:** один разработчик, умеющий работать с веб-интерфейсом и сервером; преподаватель для реальных карточек и проверки учебных правил; участники пилота. Для пилота отдельные дизайнер и тестировщик не обязательны.

**Размещение на Railway** (сверено с документацией 5 ноября 2026 года):

- [Тариф Hobby](https://docs.railway.com/pricing/plans) стоит $5 в месяц и включает $5 использования; сверх этого оплачивается разница. Расценки: память $10 за ГБ, процессор $20 за vCPU, том $0,15 за ГБ в месяц, исходящий трафик $0,05 за ГБ. Лимит тома на Hobby — 5 ГБ.
- [Адрес `.railway.app` и HTTPS-сертификат](https://docs.railway.com/networking/public-networking) предоставляются сразу, отдельный домен для пилота не нужен.
- [Резервные копии](https://docs.railway.com/volumes/backups) нужно включить в настройках: ежедневные хранятся 6 дней, еженедельные 27, ежемесячные 89. При очистке тома копии удаляются, а восстановление возможно только в том же проекте. Поэтому дополнительно нужен регулярный `pg_dump` во внешнее хранилище.
- Рабочий бюджет пилота — ориентировочно $15–40 в месяц. Это расчётный запас, а не фиксированный тариф.

## 11. Риски и открытые вопросы

Продуктовые вопросы, блокирующие разработку, закрыты. Остаются внешние риски.

| Риск | Что сделать | Когда |
| --- | --- | --- |
| **152-ФЗ.** Railway размещает данные вне РФ, а среди учеников могут быть граждане РФ. С 1 июля 2025 года действует [новая редакция ч. 5 ст. 18](https://rulaws.ru/acts/Pismo-Mintsifry-Rossii-ot-12.05.2025-N-P25-44929/) о локализации. Выводы плана основаны на вторичных источниках и не являются юридическим заключением. | Получить заключение юриста: можно ли использовать Railway, нужны ли согласие, политика обработки данных и процедура удаления. При отрицательном ответе перенести сервис и базу к российскому провайдеру; код к Railway не привязывается. | До подключения реальных учеников |
| **Доступность Telegram в РФ.** Роскомнадзор [подтвердил замедление](https://novayagazeta.eu/amp/articles/2026/02/10/telegram-snova-blokiruiut-v-rossii) в феврале 2026 года; текущий статус не проверен. Весь продукт зависит от этого канала. | Проверить работу бота у пилотных учеников из РФ. | Перед пилотом |
| **Несовершеннолетние.** В пилоте их нет, но техническая проверка возраста не предусмотрена: за это отвечает преподаватель. | Предупредить преподавателя. Перед расширением оформить согласия родителей. | Перед пилотом и перед расширением |
| **Тестовые карточки.** Реальные спорные переводы пока не проверены. | Прогнать материалы преподавателя через импорт и проверку ответов. | Перед пилотом |
| **Вход на localhost.** Документация Telegram этого не подтверждает. | Проверить на этапе 2, при необходимости использовать HTTPS-туннель. | Этап 2 |

**Отложено до итогов пилота:** допуск к опечаткам; массовое добавление слов в копии; полный экзамен по словарю; удаление данных по запросу, если юрист не потребует его раньше; подключение несовершеннолетних.
